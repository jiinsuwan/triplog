# 카드 PoC v3 — "사진 위 다꾸 overlay"로 방향 복귀

> **이 문서가 카드 미감 PoC의 현행 정본이다.** v2([card-poc-v2-report.md](card-poc-v2-report.md))는 방향이 틀려 폐기한다(아래 §1).

- **레퍼런스(고정)**: 원본 사진을 풀블리드로 깔고, 그 위에 **얇은 흰 손글씨 객체 주석 6~10개 + 작은 곡선 점선 화살표 + 얇은 흰 스케치 외곽선(접시) + 작은 흰 장식 + 하단 가벼운 마무리 한 줄**. 갈색 배경/큰 제목/해시태그 패널은 **없다**.
- **포맷**: 세로 **1080×1920** (requirements F07 P0 스펙), 사진 cover-fit 풀블리드.
- **코드**: `render-overlay.mjs`(렌더) · `overlay-place.mjs`(배치) · `overlay-prep.mjs`(사진→1080×1920 좌표) · `freespace.mjs`(점유맵/밝기) · `overlay-data.mjs`(객체·문구) · `overlay-exp.mjs`(양산) · **`editor-overlay.html`**(드래그 편집기). **현 위치 = `poc/card/legacy-v3/`** (PR #61 정리 — 외곽선 PoC 현행 정본은 [card-poc-v12-report](card-poc-v12-report.md)).
- **재현**: `cd poc/card/legacy-v3 && node overlay-exp.mjs` → 시안 + 레퍼런스 비교. 편집기는 같은 위치에서 `python3 -m http.server 8000` 후 `editor-overlay.html`.
- 이미지 경로는 이 문서 기준 상대(`../../poc/card/out/v3/...`).

## 1. v2가 틀린 이유 — 그리고 왜 놓쳤나

v2는 "갈색 배경 카드 + 상단 큰 제목 + 하단 해시태그/정보 패널"의 **포스터/잡지형 레이아웃**이었다. 이는 과거 회고([card-poc-methods-report.html](card-poc-methods-report.html))에서 **1단계 "캡션형(잡지 표지)"으로 이미 시도→기각**된 방향이다("따로 노는 느낌, 인스타 다꾸 톤과 거리"). 즉 v2는 **이미 버린 방향으로 되돌아간 것**이고, 그 과정에서 핵심(사진 위 꾸밈)을 제거했다.

원인: **과거 실패 기록을 먼저 확인하지 않고**, "v1보다 덜 산만한가"를 기준으로 삼았다. 올바른 기준은 처음부터 **"레퍼런스처럼 보이는가"**였어야 했다. 회고 문서 3단계("흰 손글씨 낙서 — 박스 제거, 사진 위 흰 펜 글씨 + 점선")가 정답 방향이었고, 학습 포인트는 **"배경을 (국소로) 어둡게 해야 글씨가 산다"**였다.

진행 경과 한눈 비교: `../../poc/card/out/v3/progression_9717.png`
`v1 rich(과밀·유치)` → `v2(잘못된 카드/제목형)` → **`v3(사진 위 overlay)`** → `레퍼런스`

## 2. v3 접근 — 사진 위 overlay

캔버스 = **세로 1080×1920 (F07 P0 스펙)**, 사진은 **cover-fit 풀블리드**(여백 밴드 없음 → 9:16 넘치는 부분 크롭). 객체 앵커/접시 폴리곤은 cover 변환(`overlay-prep.mjs`)을 거쳐 캔버스 좌표로 옮기고, 크롭으로 화면 밖에 나간 객체는 자동 제외. ⚠️ 테스트 사진 IMG_9717·8247은 원본이 1600×1600 **정사각**이라 9:16로 만들면 좌우가 크게 잘려 여백이 줄고 레퍼런스만큼 산뜻하지 않다 — **스토리(9:16)에 맞는 세로/여백 있는 사진을 쓰는 게 유리**(IMG_9800은 1200×1600이라 잘 맞음). 크롭 위치 조정(사진 팬)은 다음 편집기 기능. 그 위에 코드가 다음을 얹는다.

| 요소 | 구현 | 레퍼런스 대응 |
|---|---|---|
| 객체별 흰펜 주석 | `overlay-place`가 객체 앵커 주변 **빈 공간**에 작은 노트 배치(occupancy 최소+가장자리+분산) | 음식 옆 손글씨 메모 |
| 곡선 점선 화살표 | 노트→객체 가장자리, 짧고 얇게 + 작은 화살촉 | 작은 곡선 화살표 |
| 얇은 흰 스케치 외곽선 | **정확한 마스크(SAM 접시 윤곽)가 있을 때만**. 없으면 그리지 않음 — 일반 타원은 물체와 어긋나 "떠 보임"이라 틀린 외곽선보다 없는 게 낫다 | 접시/잔 외곽선 |
| 작은 흰 장식 | ♡ ✦ ☆ ☀ ◡ · 노트 끝/마무리 근처, 총량 캡 | 하트·반짝이·별 |
| 마무리 한 줄 | 하단 중앙, 가벼운 손글씨(제목 아님) | 하단 마무리 문구 |
| 가독성 | **국소 소프트 음영**(밝은 곳일수록 강) + 약한 글씨 그림자 | "배경 어둡게 해야 산다"의 비파괴 버전 |

**제거**: 갈색 배경, 상단 제목 밴드, 하단 해시태그/정보 패널, 큰 타이틀.

폰트: 주석 = **East Sea Dokdo**(얇은 펜), 마무리 = Nanum Pen Script. 강조 1색(크림 흰 `#fdf8ee`) — 회고 리서치 가이드(폰트 1~2종, 강조 1색) 준수.

## 3. 결과 — 레퍼런스 대비

레퍼런스와 같은 행 비교: `../../poc/card/out/v3/compare_vs_reference.png`
개별: `IMG_9717_overlay.png`(접시 4개 SAM 외곽선), `IMG_8247_overlay.png`, `IMG_9800_overlay.png`(세로).

- 풀블리드 사진 위 흰펜 주석 5~6개 + 점선 화살표 + 외곽선 + 장식 + 마무리 → **레퍼런스와 같은 계열**로 진입.
- 빈공간 추정(occupancy)이 노트를 음식 위가 아니라 테이블/트레이 **틈**에 둔다. 밀집 사진(9717)은 분산 페널티로 뭉침 완화.
- 국소 음영으로 밝은 바탕 위에서도 흰 글씨 가독.

**판단 근거**: 9717(밀집)·8247(여백)·9800(세로) 모두에서 동일 규칙이 재현됨. 8247/9800은 여백이 많아 거의 레퍼런스 수준, 9717은 식탁이 빽빽해 일부 노트가 접시 가장자리에 근접(개선 여지).

## 4. 선택형 객체지정 — overlay 패러다임에서 (Phase 3)

**`editor-overlay.html`** (정본 편집기, 1080×1920). 자동 overlay를 띄우고 사용자가 직접 편집한다. 데모: `../../poc/card/out/v3/editor_drag_demo.png`(주석 드래그 이동), `editor_add_outline.png`(클릭 추가 + 강조 외곽선).

- **주석 드래그 이동** — 모든 주석은 클릭 선택 후 드래그로 위치 변경. 옮기면 화살표가 객체를 계속 가리키도록 따라온다(수동 위치 `npos`가 자동 탐색을 덮어씀).
- **클릭으로 주석 추가** — 강조할 음식을 클릭하면 그 지점을 가리키는 주석이 추가됨(앵커=클릭 위치).
- **원형 도구 재설계** — 이전의 어색한 프리핸드 드래그를 버리고, 선택한 주석에 **강조 외곽선(원) 토글 + 크기 슬라이더**. 원이 정확히 그려져 "떠 보임" 없음. 클릭 추가 기본은 외곽선 없음.
- 문구 편집(textarea)·장식 선택·삭제·자동위치 복귀·PNG 저장. 기존 `editor.html`(구 카드 스펙)의 선택·드래그 패턴을 overlay에 맞게 가져옴.

## 5. 토큰/비용

구조 동일: 비전/배치/외곽선/장식 = **로컬 코드($0)**, LLM = **짧은 객체 문구만**. overlay는 노트가 6~10개라 v2보다 문구가 약간 늘지만 각 6~12자 → 카드당 출력 **~120~180 토큰** 수준(여전히 전체 JSON 생성 대비 5~8× 절감). 비전 API 카드당 없음.
- 권고: 객체별 짧은 문구만 LLM에 맡기고(`{objects:[{label,note}], closing}` 스키마), 위치·화살표·외곽선·장식·가독성은 전부 코드. 토큰·지연·안정성 유리.

## 6. 남은 한계 / 다음 단계

1. **밀집 사진 배치** — 9717처럼 빈 공간이 좁으면 노트가 접시 가장자리에 닿음. 개선: occupancy 임계 적응, 노트를 더 작게/2줄 고정, 필요 시 노트 수 자동 감축.
2. **자동 객체 검출** — 현재 앵커는 9717만 SAM 폴리곤, 나머지는 큐레이션. 제품에선 경량 검출(또는 사용자 원형 지정)으로 앵커 공급. 의미 라벨(노트 문구)은 저빈도 비전/LLM.
3. **외곽선은 마스크 의존** — 현재 8247처럼 마스크 없는 사진은 접시 외곽선이 없다(틀린 타원을 안 그림). 레퍼런스처럼 모든 잔·접시에 깔끔한 윤곽을 넣으려면 객체별 경량 검출(원형 접시=타원 fit, 트레이=사각)이나 사용자 원형 지정이 필요. 이게 다음 핵심 과제.
4. **베이스 사진 품질** — 레퍼런스는 밝고 여백 많은 햇살 사진이라 흰 주석이 산뜻하게 산다. 테스트 사진 중 9717(어둡고 빽빽한 실내 식탁)은 overlay 기법이 같아도 덜 산뜻하다. 톤 확정은 여백 많은 밝은 사진으로 먼저 하는 게 유리(회고에서도 같은 결론).
5. **문구 LLM 연동** — 객체별 짧은 노트 생성 스키마 고정 후 실 토큰 실측.
6. **편집기 통합** — 자동 overlay → 노트 드래그/문구 수정/추가·삭제 → export. 렌더러가 브라우저·Node 공유라 통합 저비용.
