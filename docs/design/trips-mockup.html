TRIPS — 디자인 정의 (Sprint 4 · 이 목업이 구현 정본 · 0623 시안 + 실제 프론트 구조/문구)
  • 진입 목록(티켓) → 미리보기 팝업(여행 개요) → 탐색(① 장소 담기) → 일정(② 배치). 둘은 같은 `/trips/:id/places`, 상단 단계 표시로 이동
  • ① 새 여행 / ⑤ 정보 수정 지역·테마 = 자유 입력, 해시태그 = 태그 입력(칩+Enter). 새 여행·정보 수정 동일 필드. 상태는 날짜로 자동(입력 없음). 백엔드가 태그 미지원이면 지역·테마를 태그로 노출(폴백)
  • ②③④ 미리보기 팝업 상단 정보(상태·지역·테마·기간·담은 장소 수) + 좌 지도 + 우 DAY 탭 일정. ③ 계획 0 = 빈 안내 / ④ 다녀옴 = 일정 + 도장(상단 우측, 클릭 = 추억 만들기) → "추억 만들러 가기"
  • ⑥ 장소 담기 좌 검색·카테고리·결과(출처 배지·평점·담기) / 중앙 지도(재검색·줌) / 우 보관함(✕) + "일정 배치하기 →" (실제 TripPlaceSearchView 구조)
  • ⑦ 일정 배치 DAY 탭(좌측 상단) + 시각 타임라인. stop = 시간 블록: 끌어 시각 이동 / 아래 끝 늘려 체류시간 조정(최소 1시간, 30분 단위). 시간 범위는 위·아래로 늘릴 수 있음(기본 09–21). 이동수단 = 클릭 토글(도보·자동차·대중교통)
  • 컴포넌트 design-system.css 재사용(modal·badge·btn·empty-state·stamp). 지도·캘린더·타임라인은 화면 전용 룩(실제 지도 = 카카오맵)
