## 배경

Sprint 1 중 trip 트랙이 `sprint-1.md` 정본에 없던 범위 외 작업을 발행했다 — 이슈 #28(장소/지도 화면)·#29(일정 빌더) = PR #30·#31. 두 PR이 **stacked**(#30 base=trip03 브랜치, #31 base=#30)로 만들어지면서 세 가지 문제가 드러났다.

1. **CI 자동 트리거 실패** — `ci.yml`이 `pull_request: branches:[main]`이라 base가 main인 PR에만 CI가 돈다. stacked PR은 base가 main이 아니라 자동 검사가 안 됐고, #27 CI를 수동으로 깨워야 했다.
2. **회귀 위험** — #30의 base(trip03)는 detail 라우트 보호 수정(`fec8ed1`)보다 옛 상태라, 그대로 머지하면 이미 main에 있는 보호를 되돌린다.
3. **라우트 보호 누락 재발** — `requiresAuth` 컨벤션이 `router/index.js` 주석에만 있어 #27(detail)·#30(places)에서 누락. 주석-only 규칙은 계속 샌다.

## 결정

### D1. #28·#29 이월
- **#28 → Sprint 2** — 카카오맵 SDK 장소·지도 탐색 화면(S2-TRIP-02)에 흡수. **#29 → Sprint 3**(일정 에디터).
- 두 화면 목업은 **참고 자산으로 보존**, 실 SDK·DB로 **재작성**. PR #30·#31은 **머지하지 않고 Draft 전환 + base를 main으로 변경**, 제목 prefix `S2-`/`S3-`로 정정.

### D2. stacked 금지 (base=main 독립 브랜치)
- 각 PR은 main 기준 독립 브랜치. 앞 PR 위에 쌓지 않는다. 이미 conventions §1-2에 있던 규칙의 **재확인 + 근거 명문화**(CI 자동 트리거 · 회귀 방지). 의존성은 mock으로 독립 진행 후 결합.

### D3. self-merge 게이트 (AI 자기편향 보완)

> ⚠️ **대체됨 (2026-06-12)**: 본 D3의 self-merge 게이트는 Sprint 2 회고에서 폐지 — [decisions/0007 D1](0007-pr-process.md)(상호 리뷰 단일화)이 대체한다. "객관적으로 검사 가능한 규칙은 자동 테스트로 강제" 원칙은 0007 D3(PR guardrail)로 계승된다.

트랙 내부 변경을 리뷰 없이 머지하려면: ①자기 트랙 범위(공유 영역 미접촉) ②CI green(base=main) ③**냉정한 리뷰 1회 — 새 세션의 적대적 리뷰, 가능하면 다른 AI**(예: Codex), PR 코멘트로 남김 ④사람의 빠른 최종 확인. 공유 영역(core)은 종전대로 상대 리뷰(§6-3).

### D4. 라우트 보호 컨벤션 명문화 + 자동 테스트
- 보호 라우트는 `requiresAuth` 명시, **기본=보호·공개만 명시 목록**. `router/index.spec.js`에 "공개 목록 외 전 라우트에 `requiresAuth` 존재" 테스트를 추가해 **자동 강제**(Sprint 2 S2-CORE-02).

## 근거 — 왜 "냉정한 다른 관점"인가
AI 에이전트는 자기 작업물에 덜 냉정하다(같은 맥락·소유 편향). 따라서 self-merge의 빠른 진행을 살리되, 리뷰어를 사람에서 **맥락 없는 다른 세션/다른 모델**로 대체해 객관성을 확보한다. 같은 모델이라도 새 세션은 맥락 투자가 없어 더 냉정하고, 다른 모델은 맹점이 달라 더 잘 잡는다. **객관적으로 검사 가능한 규칙은 리뷰(확률적)가 아니라 자동 테스트(확정적)로 강제**한다 — requiresAuth가 두 번 샌 것이 근거.
