## 배경

기획서 v1(2026-05-08)은 "여행 계획"과 "기록·공유"를 비슷한 비중으로 다뤘다. 2주 집중 개발 일정과 2인 팀 규모를 고려할 때 양축 동시 진행은 무리이며, AI 일정 자동 생성은 사용자 성향에 따라 만족도 편차가 커 통제하기 어렵다고 판단했다.

## 결정

TripLog는 **기록·공유 축에 집중**하고, 여행 계획은 보조 기능으로 축소한다.

### 한 줄 정의 변경

| | 정의 |
|---|---|
| v1 (2026-05-08) | 여행을 계획하고, 다녀와서 인스타에 올릴 콘텐츠를 AI가 만들어주는 서비스 |
| **v2 (2026-05-22)** | **지도 기반 여행 계획 · 사진 기반 여행 기록 · AI 기반 공유 콘텐츠 생성을 연결하는 여행 로그 서비스** |

### 빠지거나 줄어드는 것

- **경로 추천 / TSP 최적화** 제거 — 옛 EnjoyTrip 알고리즘 #4 폐기
- **AI 자동 일정 생성** P0 → **P2로 강등 또는 제외**
- **일정 에디터의 지도 동선 표시** 단순 위치 핀 수준으로 축소
- **게시판 / Q&A / 관리자 페이지** 제외
- **AI 회고록 글 자동 생성** P2 또는 제외

### 남기고 키우는 것 (P0 핵심)

1. 여행 계획 (가볍게) — 여행 만들기, 날짜별 장소·메모 기록
2. 사진 업로드 & 정리 — EXIF 위치·시간 자동 추출, 여행별 묶음
3. **사진 꾸미기 (감성 카드)** — AI 분석 → JSON → Canvas 합성 → PNG (PoC 통과 필수)
4. SNS 공유 — PNG 다운로드 후 사용자 직접 업로드

### 새로 검토 항목

- **영상 만들기 (옵션)** — 꾸민 사진을 슬라이드쇼로. PoC 후 P1 여부 결정. 잠정 클라이언트 합성(`ffmpeg.wasm`).

## 근거

- 2주 집중 개발 + 2인 → P0 최소화가 안전
- AI 일정 생성은 결과 통제 어려움 (사용자 성향 편차, 비결정성)
- 카드 생성은 PoC 가설이 명확하고 합격 기준이 측정 가능 ([poc/card-poc.md](../poc/card-poc.md))
- 인스타 공유라는 명확한 사용자 시나리오가 차별점

## 영향

- `docs/requirements.md`의 P0/P1/P2 배치에 직접 반영
- 블루프린트 §6 (AI 기능 범위) 결정과 일관
- 옛 EnjoyTrip 알고리즘 README(`archive/구버전_산출물/`)는 참고용으로만 보관
