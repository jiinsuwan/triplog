# 카드 PoC v2 — 자동 초안 미감 개선 + 선택형 객체지정 PoC 결과

- **사이클 목표**: ① 자동 생성 초안의 미감 품질을 "조금만 고치면 쓸 수 있는" 수준으로 끌어올리기 ② 선택형 객체지정(강조) 기능의 가능성 검증
- **방식**: 비전=경량 CV(오픈소스/로컬), 배치=코드/규칙, LLM=짧은 문구만
- **작업 위치**: `poc/card/` (코드), `poc/card/out/v2/` (시안)
- **재현**: `cd poc/card && node experiment.mjs` → 시안 양산 / `python3 -m http.server 8000` 후 `workbench.html` → 객체지정 PoC
- 이미지 경로는 모두 이 문서 기준 상대경로(`../../poc/card/out/v2/...`).

## 1. 현재 상태 진단 요약 (Phase 1)

기존 v1 구조: **LLM이 카드 전체 JSON(좌표·화살표·원·스티커·해시태그까지)을 길게 생성** → 정적 `out/cards/*.json` → `render-core.mjs`가 렌더. 시안 4장(음식 사진)을 직접 확인해 미감 문제를 다음으로 진단했다.

| 영역 | v1의 문제 | 근본 원인 |
|---|---|---|
| 배치/밀도 | 음식 위에 거친 원·화살표·스티커가 겹쳐 산만·유치 | **빈 공간 회피 로직 부재** — 좌표를 LLM 감으로 찍음 |
| 폰트 | NanumPen+Gaegu 둥글둥글, 유치 | 손글씨 톤이 "얇은 펜"이 아니라 "둥근 낙서" |
| 객체 인식 활용 | SAM 마스크가 *외곽 점선 그리기*에만 쓰임 | 마스크를 **배치 근거(occupied area)** 로 안 씀 |
| 일관성 | rich는 과밀, polaroid는 해시태그 화면밖 잘림 | 밀도 캡·폭 맞춤 없음 |
| 상대적 양호 | `minimal`(제목+여백)이 그나마 쓸 만 | → "여백 + 얇은 글씨" 방향의 힌트 |

핵심 결론: **이번 문제의 본질은 외곽선 정밀도가 아니라 배치·밀도·계층·여백·폰트.** 진단대로 우선순위를 폰트 → 배치 → 객체기반 빈공간 → (외곽선은 후순위)로 잡았다.

비교: `../../poc/card/out/_v1_renders/IMG_9717_rich.png` (v1) ↔ `../../poc/card/out/v2/before_after_9717.png` (v1 vs v2 4종)

## 2. 이번 실험에서 변경한 항목

1. **폰트 신규 소싱** — OFL/상업가능 한글 손글씨 5종 다운로드(East Sea Dokdo, Dokdo, Nanum Brush Script, Gugi, Stylish). `poc/card/fonts/`.
2. **경량 CV 점유맵(`freespace.mjs`)** — torch/SAM 설치 없이 사진을 48×48 격자로 보고 셀별 busyness(엣지+분산+채도+중앙prior) 계산. 기존 foodmask가 있으면 합성. **"어디가 음식이고 어디가 비었나"를 로컬에서 추정.**
3. **코드 기반 배치 엔진(`placement.mjs`)** — LLM이 아니라 알고리즘이 위치 결정. 제목=큰 여백 밴드, 메모=빈공간 우선+음식 회피+멀면 점선 꼬리, 정보=하단 밴드 폭 자동맞춤, 밀도 캡.
4. **렌더러 보정(`render-core.mjs`)** — 캡션 halo 강도 옵션화(무거운 2겹 검정 → 약한 1겹), 해시태그 폭 자동축소(잘림 버그 수정), 정보 기본 폰트 Stylish.
5. **거친 원·산만한 스티커 기본 제거** — 강조는 *요청 시에만* 얇은 흰 점선 타원.
6. **객체지정 워크벤치(`workbench.html`)** — 원형 지정 + 자동 후보 클릭.

## 5. 유망한 자동 초안 방향 2~3개

1. **방향 A — 펜 미니멀(최우선 기본값)**: 정사각 사진 + 상/하단 큰 여백 밴드, 제목(East Sea Dokdo)·정보(Stylish)만. 실패 위험이 가장 낮고 "수정할 맛"이 난다. **신규 사용자 기본 프리셋 후보.**
2. **방향 B — 펜 메모 + 꼬리**: A에 빈공간 메모 1줄 + 음식 가리키는 점선 꼬리. 감성·정보량을 더하되 회피 규칙으로 안전. **음식 단일 히어로 사진에 적합.**
3. **방향 C — 붓 제목 감성**: 제목만 붓글씨로 무드 강화. 풍경·분위기 사진에 잘 맞음(4663).

공통 골격(재현 규칙): 정사각 사진 중앙 + 상하 여백 밴드 / 제목=밴드 / 메모=빈공간+꼬리 / 정보=하단 폭맞춤 / 강조는 옵션.

## 7. 선택형 객체지정 기능 PoC 결과 (Phase 3)

워크벤치(`poc/card/workbench.html`)에 **두 방식 모두** 구현·검증. 기본은 *자동(강조 없음)* 으로, 강조는 모드를 켤 때만 동작 → **자동 흐름을 해치지 않음**(성공 기준 충족).

데모: `../../poc/card/out/v2/workbench_pick.png`(후보 클릭), `../../poc/card/out/v2/workbench_circle.png`(원형 지정)

| 항목 | ① 후보 클릭 | ② 원형 지정 |
|---|---|---|
| 동작 | 자동 분리 후보(점유맵 연결성분) bbox를 클릭 | 사진 위를 드래그해 원 영역 지정 |
| 직관성 | 높음(고를 것이 보임) | 매우 높음(원하는 곳을 바로 동그라미) |
| 구현 난이도 | 중(연결성분 라벨링 필요) | 낮음(드래그→원) |
| 정확도 의존 | **객체 분리 품질에 의존** — 마스크 없으면 후보가 뭉치거나 적음(9717=2개) | 분리 품질과 무관, 사용자 의도 직접 반영 |
| 결과 | 강조=얇은 흰 점선 타원 + 메모가 그 지점을 점선 꼬리로 가리킴 | 동일 |

**판단**: PoC 단계 우선순위는 **② 원형 지정**. 구현이 가볍고, 객체 분리 품질에 흔들리지 않으며, "애매할 때 직접 지정"이라는 보조 기능 취지에 가장 맞다. ①은 분리 품질이 좋아지면(마스크 보유 사진) 보완 옵션으로 함께 제공. **올가미는 불필요 확인.**
효과: 강조 지정 시 메모가 그 객체를 가리키도록 배치가 바뀌어 **결과가 실제로 개선**됨(자동이 애매한 케이스에서 유용).

## 8. 토큰/비용 관점 정리 (Phase 4)

**구조 변화가 핵심.** v1은 "LLM이 카드 전체 JSON을 길게 생성", v2는 "LLM은 짧은 문구만, 배치는 로컬 코드".

| 단계 | v1 | v2 | 비용 영향 |
|---|---|---|---|
| 비전(객체/빈공간) | 비전 API 호출(이미지 토큰) | **로컬 경량 CV** | **API 비용 0** + 오프라인 |
| 레이아웃 | LLM이 좌표·배열 생성(긴 출력) | **로컬 placement 코드** | **LLM 출력 0** |
| 문구 | 전체 JSON에 포함 | LLM이 **제목+메모+해시태그 3개**만 | 출력 토큰 대폭 감소 |

**토큰 추정(카드 1장, 근사)**
- v1: 입력 ~600–900 + 출력 ~700–1000(JSON) + 비전 호출(이미지 ~1000–1500). 출력가가 입력가의 3–5배라 **출력이 비용 지배**.
- v2: 입력 ~200–350(장소·무드·라벨 일부) + 출력 ~**50–90**(짧은 문구 JSON). 비전 API **없음**.
- → **LLM 출력 토큰 약 10–15× 절감**, 카드당 비전 API 제거.

**비용 밴드(모델·시세 의존, 근사·예시)**: 소형 모델(예: Flash/4o-mini/Haiku급) 기준 v2 문구 호출은 카드당 대략 **$0.001 미만**, 목표 $0.025–0.03 대비 큰 여유. 로컬 CV·배치는 **$0·수십 ms**. (정확한 단가는 채택 모델·현재 시세로 재확인 필요.)

**실서비스 권고**
- "긴 JSON 생성" 구조 폐기 → **"짧은 문구 생성 + 코드 배치"** 채택. 토큰·지연·안정성 모두 유리.
- GMS 키 토큰 예산이 빠듯해도 v2의 출력 규모면 여유. 문구 호출은 batch/캐시 가능.
- 의미 라벨이 필요하면 **선택적·저빈도** 비전 호출로 분리(이번 사이클에선 불필요).

## 9. 다음 단계 추천

1. **A_penclean을 기본 프리셋으로 채택**, B/C는 사용자 선택지로. (가장 안전한 자동 초안)

6. (후순위) 외곽선/누끼 강조는 강조 모드의 *옵션 효과*로만.
