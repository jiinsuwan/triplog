## 배경

Sprint 2 기간 PR 12건을 회고 시점에 전수 실사한 결과:

1. **reviewer 지정 = 0/12건** — 머지 게이트(Approve)는 브랜치 보호로 강제되고 있었으나, PR 발행 시점에 상대에게 알림이 가는 경로가 없었다.
2. **본문 형식 파편화** — 표준 템플릿 / 자유 형식(#49·#51·#52) / 헤더 한글 변형(#60)이 혼재. 내용은 대체로 충실했으나 형식이 통일되지 않아 기계 검사가 불가능한 상태.
3. **PR 발행이 사람 지시에 의존** — 작업 완료 후 agent가 발행 단계를 누락하고 코멘트로 갈음하는 사례 반복. 사람 지시 의존이 PR #60·#63 본문에 그대로 기록되어 있다.

S1 회고 교훈("주석-only 규칙은 샌다 → 객관 규칙은 테스트로 강제")이 PR 프로세스에서 재현된 것이다.

## 결정

### D1. self-merge 게이트 폐지 → 상호 리뷰 단일화

- 0005에서 신설한 self-merge 게이트(구 conventions §1-3)를 폐지한다. **모든 PR = 상대를 reviewer로 지정 + 상대 Approve 후 머지.** 트랙 내부 변경도 예외 없음.
- 리뷰 응답 SLA는 두지 않는다 — 2인 팀, 급하면 직접 연락으로 충분.
- 적대적 리뷰(0005)는 별도 게이트가 아니라 **상호 리뷰의 리뷰어 측 역할로 흡수**된다.

### D2. PR 발행 규칙

- 작업 완료(AC 충족 + 로컬 테스트 통과) 시 **PR 발행 단계를 건너뛰지 않는다.** 코멘트·요약 보고로 갈음 금지.
- 발행은 **사람에게 명시적 확인을 받은 뒤** 한다 — 자동 발행이 아니다. 사람 게이트 유지.
- 발행 시 **상대를 reviewer로 지정**한다 (GitHub 알림 경로 확보).

### D3. PR Guardrail — proposal #59 제안 3건 전부 채택

1. **본문 검사 CI** — feat·fix PR = required check(머지 잠금), docs/chore = 경고만, Draft = 스킵. 전제 = 템플릿 헤더 문구 고정(번역·변형 금지). required check 설정(ruleset) 가능 여부는 구현 시 선행 확인 — 불가 시 "CI 표시 + 컨벤션"으로 강도 하향.
2. **공유 경로 감지** — CI fail이 아니라 **자동 코멘트 + `track:core` 라벨**(제안자 권고: fail은 우회 습관을 만든다). 경로 목록 확정(`frontend/src/api/config.js`·`backend/.../user/` 포함 여부)은 구현 이슈에서.
3. **API 계약 테스트 기준표** — [conventions §8-2](../conventions.md). API 신규/수정 Issue/PR은 Test Criteria 작성 시 표에서 해당 항목을 골라 명시(전 항목 테스트 코드화 의무 아님).

- 회고 후 보강: **reviewer 미지정 경고 코멘트**도 검사 항목에 포함.
- 구현 = Sprint 3 core Issue(#65). CI 도입 전까지는 수동 준수 구간.

### D4. 알림·감지 자동화 = 각자 자율

컨벤션은 결과(reviewer 지정·리뷰 수행)만 규정한다. 알림 수신·리뷰 준비 방식(메일/앱/로컬 자동화)은 툴체인 자유([conventions §9-3](../conventions.md))의 사적 영역.

## 근거

- 실사 수치(위 배경)가 "규칙은 있었으나 이행이 흩어짐"을 보여줌 — 규칙 신설이 아니라 **이행 강제** 문제.
- 분기 있는 규칙(self-merge 가능/불가 판단)은 해석 여지를 만든다 — 분기 없는 단일 규칙 + 기계 검사로 사람 기억 의존을 줄인다.
- 형식 파편화의 실증: 회고 준비 중 1차 기계 검사가 한글 변형 헤더를 "누락"으로 오판 — 헤더 고정이 검사 도입의 전제임을 직접 확인.
