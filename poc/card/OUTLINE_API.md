# 외곽선 모듈 JSON 계약 (PoC v12)

> 소비자 둘: **(1) 웹 에디터** (1차 초안 표시 + 탭/박스 보정), **(2) LLM 판단 계층** (후보 중 선택·묶음,
> 코멘트/스티커 배치 — GMS 텍스트 LLM, 이미지 생성 아님). 구현: `outline_module.py` (코어),
> `serve_outline.py` (FastAPI 사이드카). 배포 권고 근거는 [`DEPLOY_RESEARCH.md`](DEPLOY_RESEARCH.md).

## 좌표 규약

- 모든 좌표 **0~1 정규화** `[x, y]` (원본 해상도 무관, 에디터 캔버스 크기와 독립).
- 폴리곤 = 닫힌 루프. 한 항목이 루프 여러 개를 가질 수 있음 (떨어진 무리 = 한 묶음).
- 선 스타일(굵기·점선·색·여백)은 **계약에 없음** — 전부 에디터/렌더러 파라미터.
  여백(객체-선 간격)만 `group.margin`처럼 추출 시점 파라미터가 존재 (오프셋이 기하에 반영되므로).

## 1. 업로드 전처리 (자동 초안)

`POST /v1/images` (multipart `file`) →

```json
{
  "image_id": "a1b2c3d4e5f6",
  "elapsed_s": 12.3,
  "meta": {"sal_mass": 0.31, "fallback": false, "dropped": 6,
           "carriers": [{"label": "tray of food", "conf": 0.73, "xyxy_norm": [0,0.05,0.94,0.99]}],
           "t_detect": 6.6, "t_sam": 2.2},
  "items": [
    {"id": 0, "label": "coffee cup", "conf": 0.64, "src": "det",
     "bbox": [0.64, 0.42, 0.75, 0.70], "center": [0.69, 0.55], "area": 0.018,
     "polygons": [[[0.65, 0.43], [0.66, 0.42], "..."]]}
  ]
}
```

- `src` = 항목 출처: `det`(검출) / `det-weak`(저신뢰+saliency 게이트) / `det-zoom`(운반대 확대 재검출)
  / `grid`(운반대 내부 점-격자 구제, label 없음) / `sal`(saliency 폴백·구제).
- `label`/`conf`는 **참고용** (외곽선 품질과 무관, 문구 생성 단계 입력). `grid`/`sal`은 `subject`.
- `carriers` = 여러 객체를 품어서 개별 모드에서 제외된 박스 (쟁반·불판 류). LLM이 "쟁반째 묶음"을
  원하면 이 bbox를 `box` 연산에 넘기면 됨.
- **LLM 활용**: `items`의 label/center/area/bbox만으로 (이미지 없이) "무엇을 켜고 끌지,
  무엇을 묶을지, 코멘트를 어디에 달지" 판단 가능하게 설계됨.

## 2. 에디터 보정 연산 (이산 클릭 → 왕복 1회)

| 연산 | 요청 | 의미 |
|---|---|---|
| `POST /v1/outline/tap` | `{image_id, point:[x,y]}` | 탭 = 단일 객체 (박스 헐렁함 원천 차단) |
| `POST /v1/outline/multitap` | `{image_id, points:[[x,y],...]}` | 멀티탭 = 합집합 한 묶음 |
| `POST /v1/outline/box` | `{image_id, box:[x1,y1,x2,y2]}` | 박스 = 적응형 묶음 (커버리지≥0.45 단일 / 미달 시 3×3 격자 잘게-따서-합치기) |
| `POST /v1/outline/group` | `{image_id, item_ids:[...], margin}` | 기존 item 합집합 → 느슨한 루프 (SAM 호출 없음, 즉시). 버블 모드 2종: `hull`(볼록 — 떨어진 객체 묶음용) / `smooth`(오목 유지 — 한 덩어리 대형 객체용; hull은 오목부를 질러 옆 객체까지 품는 듯 보임) — 에디터 토글 후보 |

응답 공통: `{"polygons": [...], "item_id": N}` — 에디터가 외곽선 요소(레이어)로 추가.
**모든 보정 결과(tap/multitap/box/group)도 item으로 등록**되어 `item_id`를 돌려받는다.

**기존 그룹에 빠진 부분 추가** (예: 묶음이 한 모서리를 놓침):
1. 빠진 부분을 `tap` → `item_id=k` 획득
2. `group(item_ids=[기존 그룹 id, k], margin)` 재호출 → 합집합 루프 갱신
   (group은 SAM 호출이 없어 즉시 응답 — 마스크 합집합 + 윤곽 재추출뿐)

## 2-1. 최초 1회 텍스트 배치 규칙 (LLM 판단 계층용 — 사용자가 이후 자유 조정)

자동 초안의 각 item에는 `anchors: [[x, y, score], ...]` (점수순 최대 3개)가 포함된다.
앵커는 **객체 마스크 + 외곽선 스트로크 + 안전 여백과 겹치지 않는 빈 공간** 중에서
(1) 여유 거리 (2) 어두움(흰 글씨 가독) (3) 해당 객체와의 근접으로 점수화된 좌표다.

LLM의 최초 배치 절차:

1. **코멘트를 달 item을 고른다** — 전부가 아니라 주인공·특이점 위주 3~6개
   (`area`·`center`·`label`·`src`로 판단. `src=grid/sal`은 label이 없으므로 위치·면적으로만).
2. 각 item의 `anchors[0]`(1순위)을 기본 채택. 단:
   - 이미 배치한 다른 텍스트와 같은 영역이면 `anchors[1..]`로 회피 (앵커 간 최소 간격은
     모듈이 보장하지만, **서로 다른 item의 앵커끼리는 겹칠 수 있음** — LLM이 분산 책임).
   - 화면 가장자리 0.06 이내·코너는 피한다 (날짜/마무리 문구 자리로 예약).
3. **고정 요소 규약**: 날짜+장소 = 좌상단, 마무리 한 줄 = 우하단 (ref 5장 공통 패턴).
   이 두 자리는 item 앵커보다 우선 확보.
4. 텍스트는 2줄 이내 짧은 문구 (0004 D3) — 길면 앵커 주변 빈 공간을 벗어난다.

알려진 한계 (에디터에서 사용자가 조정 가능하므로 차단 사유 아님):
- 앵커는 점 기준 — **텍스트 박스의 가로 폭은 미고려** (프레임 잘림 가능. 개선 예정: 사각 적합)
- 밝은 배경(흰 접시) 위 앵커는 흰 글씨 가독이 낮음 (개선 예정: 어두움 가중 강화)

## 2-2. LLM 응답 스키마 + 검증 계약 (S3-LOG-01)

§2-1 절차로 텍스트 LLM이 산출하는 응답의 JSON 스키마와 백엔드 검증 규칙이다.
LLM은 **객체 선택 + 짧은 문구만** 생성하고 좌표·외곽선·장식은 만들지 않는다 (0004 D3·D4).
좌표는 §1 `items`에서 가져와 렌더 단계가 해소한다. 검증 구현 = 백엔드
`com.triplog.ai.card`(`CardCaptionValidator`).

### 응답 스키마

```json
{
  "objects": [
    { "itemId": 0, "anchor": 0, "note": ["고소한 감자,", "손이 계속 가는 맛"] }
  ],
  "closing": { "text": "오늘의 만찬, 다 같이 ♡" }
}
```

| 필드 | 타입 | 필수 | 의미 |
|---|---|---|---|
| `objects[]` | array | O | 코멘트를 달 객체 목록 |
| `objects[].itemId` | int | O | §1 `items[].id` 참조 |
| `objects[].anchor` | int | 선택(기본 0) | 해당 item의 `anchors` 인덱스 (§2-1). `0 ≤ anchor < anchors 길이` |
| `objects[].note` | string[] | O | 1~2줄 짧은 문구 (§2-1.4) |
| `closing.text` | string | 선택 | 우하단 마무리 한 줄 (§2-1.3) |

**좌표·외곽선·장식 필드는 응답에 올 수 없다** (LLM 임의 좌표 생성 금지, 0004 D4).
알 수 없는 필드가 있으면 파싱을 거부한다(`AI_002`). `deco`(장식)는 LLM이 생성하지
않는다 — 0004 D3의 LLM 스키마(`{objects:[{note}], closing}`)에 없으므로 코드/사용자
영역으로 둔다.

### 검증 2단계

사이드카 의존을 분리하기 위해 검증을 두 단계로 나눈다.

1. **구조 검증** (`validateStructure`, items 불요) — 형식·필수 필드·자기완결 제약.
   GitHub Actions `backend test`의 단위 테스트 대상.
2. **참조 검증** (`validate(response, context)`, items 주입) — `itemId` 존재 · `anchor`
   인덱스 범위. 허용 `itemId` 집합과 item별 `anchors` 개수를 `ValidationContext`로
   받는다 — 사이드카를 호출하지 않으므로 픽스처로 단위 테스트가 된다. **items 조달
   경로**(백엔드가 어디서 item 목록을 받는지)는 렌더·사이드카 연동(S3-LOG-02/04)에서 정의.

| 규칙 | 구분 | 사유 |
|---|---|---|
| `objects` 누락/null | 거부 | 구조 불변식 |
| `itemId` 누락/비정수 | 거부 | 구조 불변식 |
| `note` 누락/빈/빈 줄 포함 | 거부 | 구조 불변식 (빈 줄 렌더 누수 차단) |
| 알 수 없는 필드(좌표 등) | 거부(파싱) | 0004 D4 좌표 금지 — enum 아님, `AI_002` 예외 |
| `itemId` 미존재 | 거부(참조) | items 정합 |
| `anchor` 범위 밖 | 거부(참조) | anchors 길이 인덱스 |
| `objects` 빈 배열 | 경고 | 문구 없는 카드가 됨 |
| `objects` 개수 3~6 밖 | 경고 | §2-1은 권고 — 사용자 조정 가능 |
| `note` 3줄 이상 | 경고 | §2-1.4 권고 |
| `itemId` 중복 | 경고 | 렌더 충돌 가능 |
| `anchor` 누락 | 경고 | 기본 0 적용 |
| `closing` 누락 | 경고 | 없어도 카드 성립 |

개수·줄수를 **거부가 아닌 경고**로 두는 근거: §2-1의 "3~6개·2줄"은 LLM 판단 가이드이고
"사용자가 이후 자유 조정"을 전제로 한다(§2-1 알려진 한계). 거부로 두면 사용자가 2개만
남기거나 7개를 단 정상 카드가 invalid가 된다.

### 번호 → 좌표 변환 (계약만 — 구현은 렌더 S3-LOG-04)

LLM 응답에는 좌표가 없으므로 렌더 전에 §1 `items`로 해소한다.

| 응답 | → | 좌표 출처 (§1) | 결과 |
|---|---|---|---|
| `itemId` | → | `items[id].center` | 객체 중심 |
| `itemId` | → | `items[id].bbox` | 노트 거리·외곽선 반경 |
| `itemId, anchor` | → | `items[id].anchors[anchor]` | 노트 표시 좌표 |
| `itemId` | → | `items[id].polygons` | 외곽선(선택) |

이 변환의 **구현은 렌더(S3-LOG-04) 책임**이며, 본 이슈(S3-LOG-01)는 계약만 정의한다.
다음은 검증이 막지 않는다(상위 단계 책임) — 텍스트 박스 가로폭 미고려로 인한 프레임
잘림(§2-1 한계), `grid`/`sal`처럼 label 없는 item의 문구 소재 부재(§5).

## 3. 파이프라인 내부 (참고)

```
YOLO-World(여행 어휘, conf 0.15~) ─ R1 conf≥0.30 채택
                                  ─ R2 0.15~0.30 → U2-Net saliency 겹침 시 채택
중복 제거(IoU + 포함관계) → 운반대 강등(자식≥2 박스)
운반대 확대 재검출(SAHI식) + 운반대 내부 점-격자 구제(어휘 무관, 표면조각 기각)
saliency 커버리지-갭 구제(거대 주인공 미검출 구제)
→ SAM2.1-b (박스 프롬프트 + 타이트 박스 재프롬프트) → 마스크
→ CLOSE/OPEN(7) → 오프셋 팽창(0.6% min변) → findContours → DP(0.0018) → Chaikin×2 → poly_norm
```

## 4. 성능 관측치 (CPU, M-시리즈 맥, 1280px 처리 해상도)

- 자동 초안: 검출+saliency 0.5~0.7s + SAM 1~2.5s. **운반대 격자 구제 시 +6~16s** (탭당 ~1s,
  ultralytics가 호출마다 인코딩 재실행하는 구조 탓 — 제품에선 인코딩 1회 캐시로 단축 여지 큼).
- 보정 연산: 탭 ~1s (서버 왕복 포함 시 1~1.5s — 이산 클릭 UX로 수용 범위).
- 모델 상주: YOLO-World-s + SAM2.1-b + U2-Net ≈ 가중치 550MB, RSS 2~4GB 추정(자체 계측 필요).

## 5. 한계 (정직)

- 회귀 검증은 현재 5장 + 과거 12장 결과 기준. 격자 구제·운반대 규칙은 이번 5장에서 조정됨 —
  새 유형(인물·풍경·실내)에선 운반대 오판 가능성 있음.
- `grid`/`sal` 항목은 label이 없어 문구 생성 단계에서 저빈도 Vision 라벨링(0004 D2 허용 범위) 또는
  사용자 입력 필요.
- 묶음 단위 선택은 모듈이 판단하지 않음 (개별 = 기본, 묶음 = LLM/사용자 연산) — 설계 의도.
